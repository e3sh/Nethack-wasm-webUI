# モバイル向け DOM UI システム仕様書

## 1. 概要
本プロジェクトのモバイル版 (`mobile.html`) では、従来の Canvas ベースの描画エンジンに代わり、HTML 要素を直接操作する **DOM レンダラー** を採用しています。これにより、モバイル端末での消費電力低減、文字の鮮明化、およびタイル表示の高速化を実現しています。

## 2. 構成コンポーネント

### 2.1 mobileCurses.js
`jncurses.js` をモバイル向けに再実装したクラスです。
- **軽量化**: Canvas のピクセル操作やフレーム毎の全画面クリアを廃止。
- **行ベースの更新**: 各行を `div` 要素（`.jn-line`）として保持。テキストが変化した行のみを更新することで、DOM 操作を最小限に抑制します。
- **ハイブリッド描画**: 
  - 通常のテキスト（日本語含む）はブラウザのネイティブレンダリングを使用。
  - 特殊なグリフ（タイル画像）は `span` 要素と CSS Background Sprite により描画。

### 2.2 domRenderer.js
DOM ベースでのメニュー表示や入力プロンプトのオーバーレイ管理を担当します。

### 2.3 mobile.html
モバイル専用のエントリポイントです。
- `ui-root` 要素内に `mobileCurses` が展開されます。
- `virtual-pad` 要素により、ゲームエンジン (`inputGridPad.js`) と同期したタッチボタンを表示します。

## 3. 主要機能の仕組み

### 3.1 日本語・マルチバイト文字の表示
Canvas 版ではビットマップフォントを合成していましたが、DOM 版では OS 標準の等幅フォントを使用します。これにより、ピンチズーム時も文字が美しく保たれます。

### 3.2 タイル（グリフ）表示
NetHack の各タイルは、`tileset` 画像からの CSS 切り出し (`background-position`) によって `span` 要素としてテキスト行の中に埋め込まれます。
- **グリフ判定**: 文字列中の `0x100` 以上のコード（JIS漢字圏を除く）を自動的にタイルとして識別します。

### 3.3 自動セーブ連携遷移
モバイル版からデスクトップ版（Canvas版）へ切り替える際、以下のシーケンスが自動実行されます。
1. `window.g.rogue.playing` フラグでプレイ状況を確認。
2. プレイ中の場合、`Shift+S` (Save) → `y` (Confirm) → `Space` (Finalize) を順次送信。
3. エンジンの終了（`playing` フラグの解除）を監視。
4. IndexedDB へのファイル同期を待機してから `index.html` へ遷移。

## 4. パフォーマンスへの配慮
- **差分更新**: `line.textContent !== nextText` のチェックにより、不必要な DOM 反映を回避。
- **低負荷**: アニメーションなどの GPU リソースを抑え、バッテリー消費を軽減。
