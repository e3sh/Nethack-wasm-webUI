# Game Knowledge Layer（ゲーム知識層）構想メモ

## 1. 背景と目的
NetHackは非常に奥深いゲームコンテンツ（多様なアイテム、モンスターの生態、神々の信仰、昇天への戦略など）を持っていますが、**「操作や仕様の複雑さ（システムの壁）」**によって新規プレイヤーや若い世代がその深みにたどり着く前に離脱しやすいという課題があります。

FactorioやMMORPGといった現代の複雑なゲームでも「面白さを実感できるまでの導線」が綿密に設計されています。しかし古典的なNetHack（特にRogueになかった追加要素）では「試行錯誤で理解しろ」という旧来の設計のまま止まっており、現代のプレイヤーにとってはWikiや検索・AIに頼らざるを得ないのが実情です。

本構想は、WebUI Coreの上に**「知識層 (Game Knowledge Layer)」**を独立したモジュールとして導入し、プレイ中にリアルタイムで適切な知識支援（動的ヘルプ、実行可能なコマンドパレット、設置物・死体・NPC等のインタラクティブ案内）を提供することで、ゲームコンテンツの奥深さに短時間で到達できるようにすることを目的とします。

---

## 2. プレイヤーが直面する具体的な「躓きポイント (Pain Points)」

ポータビリティやWeb化開発を行ってきた開発者自身の実体験に基づく、特にハードルの高い要素の分析：

1. **Rogueになかった設置物・地形の操作**
   * 祭壇 (Altar)、石像 (Statue)、宝箱 (Chest)、噴水 (Fountain)、シンク (Sink) 等に対し、何ができるのか（`#offer`, `#dip`, `quaff`, `kick` など）が直感的に分からない。
2. **死体・耐性・信仰・特殊アイテムのノーヒント性**
   * 「死体を捧げる/缶詰にする (Tinning Kit)」「特定の死体を食べて耐性を得る」などの解法がノーヒントに近い。フォーチュンクッキーやお告げの詩的メッセージだけでは理解不能。
3. **エリア固有ルールとNPC対話**
   * 店（盗みや支払いの概念）、倉庫番（Sokoban）、鉱山（Mines）、NPCとの対話（`#chat` コマンドの存在や意図的な非攻撃行動）の導線欠如。
4. **コマンド一覧（`?`キー）が単なるテキストで「実行メニュー」になっていない**
   * ヘルプを表示しても単なる閲覧用テキストであり、一覧からコマンドを選んでそのまま実行（発動）することができないため、キーやコマンド名を暗記して画面を閉じる必要がある。
5. **ペット・友好モンスターのシステム**
   * 初期ペットのテイム（なづけ、えさやり）や友好モンスターの挙動・扱いが直感的に理解しづらい。

## 3. 最新アーキテクチャ構成案 (GKL 4層パイプラインモデル)

```
 [ UI Layer / Custom Status UI / AI Agent / Touch Overlay ]
        │  ▲
        │  │  gkl.getSituation() / gkl.executeAction() (一元化ファサード)
        ▼  │
 ┌──────────────────────────────────────────────────────────┐
 │ 🧠 Game Knowledge Layer (GKL / 知識・状況管理層)         │
 │                                                          │
 │  1. 統合状況キャッシュ層 (Situation / State Cache)         │
 │     - SituationCache                                     │
 │       (StatusAccessor + InventoryState + AreaState)      │
 │                                                          │
 │  2. 知識補完・意味解釈層 (Knowledge Interpretation)        │
 │     - Item/Rule Resolver                                 │
 │       (未識別アイテム・属性・効能・ダンジョン知識の補完)   │
 │                                                          │
 │  3. 操作支援・推論エンジン層 (Action Reasoning)           │
 │     - ContextActionEngine                                │
 │       (統合状況から「今可能な推奨アクション」を生成)     │
 │     - DirectionalActionResolver                          │
 │       (方向キーから文脈に応じた推奨アクションの自動解決) │
 │                                                          │
 │  4. 自走実行・制御層 (Execution Controller)              │
 │     - RequestController                                  │
 │       (アクションの keySequence トークンを安全自走消化)   │
 └────────────────────────────┬─────────────────────────────┘
                              │ querySequenceSilent / executeSequence (SoC完全分離)
                              ▼
 ┌──────────────────────────────────────────────────────────┐
 │ ⚙️ WebUI Core (通信・汎用インフラ層)                     │
 │  - querySequenceSilent(tokens, options)                  │
 │  - getLastSequenceBuffer() / Event Emitter               │
 └────────────────────────────┬─────────────────────────────┘
                              │ WASM Bridge 通信
 ┌────────────────────────────┴─────────────────────────────┐
 │ 🐉 NetHack Core (WASM Engine)                            │
 └──────────────────────────────────────────────────────────┘
```

## 4. 知識層が担う主要コンポーネント & 具体的アプローチ

1. **実行可能なコマンドパレット＆カテゴリ分類UI (Executable Command Palette)**
   * `?` キーなどのヘルプを単なるテキスト閲覧で終わらせず、VS Codeのコマンドパレットのように「カテゴリ分類（行動/インベントリ/ステータス/システム）＋検索」ができ、**項目を選択・クリックするだけでその場でコマンドが発動する実行型UI**として提示。
   * **非キーボード環境への対応**: メニュー化により、キーボードを持たない環境（スマートフォン/タブレットのタッチ操作、マウス、ゲームパッド/コントローラー）でも確実かつスムーズなインタラクトが可能になる。
   * 現在の状況で実行不可能なアクション（例: 武器を持っていない時の攻撃・投擲など）のグレーアウト表示。
2. **設置物・地形のコンテキストアシスト (Contextual Actions)**
   * 祭壇や噴水、シンクに隣接・乗った際に、WebUI側で「実行可能なアクションメニュー（捧げる/飲む/蹴る/浸す等）」をポップアップ提示。
3. **死体・アイテム・伝承の知識カード (Entity & Knowledge Card)**
   * 拾ったアイテムや死体、モンスターに対し、WikiやAI不要で「この死体は食べると危険/耐性がつく可能性がある」「缶詰にできる」といったヒントを提示。
4. **Log & Context Parser (文脈・ログ解析)**
   * メッセージ内の重要キーワードを自動抽出し、ハイパーリンクやツールチップ化。
5. **NPC・エリア・ペットの導線案内 (Area & Companion Guide)**
   * 店に入った時のルール明示、NPCに近接した際の `#chat` 案内、ペットの機嫌・テイム状況の可視化。

---

## 5. 期待される効果とメリット

* **マルチデバイス・非キーボード操作の実現**: メニューUI化により、スマホ/タブレットの画面タップ、マウス操作、ゲームパッドでのプレイが直感的かつ確実に可能になる。
* **知の灯火としての役割**: プレイヤーのモチベーションを削がず、探索や実験のロマンを促進。
* **古典と現代の架け橋**: 現代ゲーム（Factorio, MMORPG等）レベルの親切な導線を構築し、古典的名作の面白さをストレートに体験可能にする。
* **独立したメンテナンス**: WebUI CoreやC言語側のロジックを変更せず、JSON辞書やWikiルールの更新だけで知識ベースを拡充可能。

## 6. 構築難易度の緩和と段階的導入案 (Phased Approach)

NetHackの複雑な仕様・例外状況をすべて網羅する知識ベースを最初から完璧に構築するのは難易度が高いため、以下のようにハードルを下げて段階的に開発するのが現実的です：

* **Phase 1: 静的コマンドパレット (難易度：低)**
  * 単に全コマンドを「行動」「インベントリ」「ステータス」「システム」等にカテゴリ分類したJSONを定義。文脈判定を行わず、選択・タップで実行できる「実行可能メニュー」を実装。
* **Phase 2: 設置物・アイテムのコンテキストメニュー & 軽量Wikiリンク (難易度：中〜低)**
  * 「祭壇」「噴水」「シンク」「宝箱」への隣接/乗った時、および「死体」選択時など、明確な特定のオブジェクトに対してのみ、固定のアクション選択肢（捧げる/浸す/飲む/缶詰にする等）を提示。
  * **軽量Wikiダイレクトリンク**: モンスター名やアイテム名をそのままWikiの検索/ページURL（例: `https://nethackwiki.com/wiki/名称`）に変換して外部リンク化。高度なDBを作らずとも名称マッチングだけで容易に実現可能（※外部サイト側のURL変更による404リスクへの配慮は必要）。
* **Phase 3: ログ解析・動的ヒント・Wiki/AI連携 (難易度：極高・非現実的)**
  * メッセージログの自動キーワード解析、詳細な識別追跡、状況に応じた動的アシスト。
  * ※ほぼ「NetHackに精通した専用ローカルAI」を構築・組み込むレベルの複雑さとなるため、現時点でのWebUI開発としては非現実的であり、近未来の技術（AI連携等）への期待・ロマン的フロンティアとして位置付ける。
