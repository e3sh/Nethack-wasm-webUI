# NetHack メッセージ翻訳フロー解説

本ドキュメントでは、`rogue/UI/trancelate.js` における翻訳エンジンの仕組み、翻訳の優先順位、データ構造、ならびにリアルタイムログ表示機能との連携について解説します。

---

## 1. 辞書データの構造

現在、全ての翻訳データは `param/nhMessage.js` 内の以下の4つの関数（辞書オブジェクト）に集約されています。

- **`nhMessage()`**: 文章全体の完全一致（メッセージログ、引用文等）
- **`nhEntities()`**: 固有名詞（モンスター名、神の名前、役割、属性等）
- **`nhItems()`**: アイテム単語（武器、防具、素材名、状態等）
- **`nhPatterns()`**: 正規表現パターン（変数を含む文章の置換ルール）

---

## 2. 翻訳の優先順位 (Engine Flow)

`get_translation_data(msg)` が呼び出されると、以下の順番でマッチングが試行されます。

```
[入力英文 (RAW)]
       │
       ├─► 1. 全文一致検索 (nhMessage) ───────────► [マッチすれば翻訳返却]
       │
       ├─► 2. 単語・エンティティ一致 (nhItems/nhEntities) ► [冠詞・複数形除去して翻訳]
       │
       ├─► 3. 正規表現パターンマッチ (nhPatterns) ───► [変数置換 & 再帰翻訳]
       │
       └─► 4. アイテム名の分解・再構成 (Item Parsing) ─► [接頭辞/接尾辞に分解して再帰翻訳]
```

1. **全文一致検索 (`nhMessage`)**
   - 原文がそのまま登録されている場合、即座に翻訳を返します。
2. **単語・エンティティ一致 (`nhItems` / `nhEntities`)**
   - 冠詞（a, an, the）や複数形を除去した単語単位の辞書引きです。
3. **正規表現パターンマッチング (`nhPatterns`) [優先度: 高]**
   - `$1`, `$2` などの変数を含む文章にマッチさせます。
   - `corpse of (.*)` のようなアイテム固有の表現も優先的にここで処理されます。
4. **アイテム名の分解・再構成 (Item Parsing)**
   - パターンに一致しなかったアイテム名を、「祝福された」「+1」「錆びた」などの接飾語と「本体名」に分解します。
   - **本体名の再帰的翻訳**: 分解された本体名は、再び手順1から翻訳にかけられます。

---

## 3. 高度な変換メカニズム

### 再帰的翻訳 (Recursive Translation)
パターンの置換文字列内の `$1`, `$2` などは、自動的に再帰処理されます。
- 例: `You hit the Jackal.`
  1. パターン `You hit the (.*).` にマッチ。
  2. `$1`（`Jackal`）を再度エンジンにかけ、`ジャッカル` を取得。
  3. `ジャッカルを攻撃した。` を出力。

### 属性（品詞）指定子 (POS Specifiers)
`Entity` や `Item` 辞書に `adj`（形容詞訳）や `verb`（動詞訳）がある場合、パターン側から明示的に呼び出せます。
- **`$1:adj`**: その単語の `Adj` カラムの訳を使用。
- **`$1:verb`**: その単語の `Verb` カラムの訳を使用。
- 例: `$1:adj 攻撃` （`$1` = `ice` なら「氷の攻撃」）

---

## 4. リアルタイムログ（`tr_log.html`）との連携メカニズム

翻訳エンジンが処理を行った際、適用結果がリアルタイムで対比ログシステムへ送信されます。

- **ログ出力**: 翻訳が成功したか失敗したか（未翻訳か）にかかわらず、元の英文（`raw`）と最終的な日本語訳（`jp`）、タイムスタンプが `localStorage` や `BroadcastChannel` 経由でブロードキャストされます。
- **並行観察**: プレイ中に `tr_log.html` を別ウィンドウで開いておくことで、エンジンがどの英文をどう翻訳したかをリアルタイムにモニタリングできます。詳細な活用方法は [翻訳支援ツール＆リアルタイム検証環境ガイド](translation_support_tools.md) を参照してください。

---

## 5. デバッグと検証環境

- **学習モード (`LANG_LEARNMODE`)**:
  設定画面 (`config.html`) または `rogueDefines.js` で有効にすると、翻訳に失敗した原文が `localStorage("nh.temp")` に自動蓄積されます。
- **未翻訳確認・管理**:
  `tr_fail.html` や `tr_manager.html` を使用することで、蓄積された未翻訳ログを一覧確認・試作翻訳できます。
- **単体テストツール (`tr_test.html`)**:
  任意の英文を入力してエンジンの挙動を個別に検証可能です。
