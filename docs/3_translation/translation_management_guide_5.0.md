# NetHack 5.0 翻訳システム統合管理ガイド

本書は、NetHack Wasm WebUI 移植プロジェクトにおける NetHack 5.0 対応の翻訳管理システム、これまで確立された技術的知見・実績、および統合管理スクリプト `manage_translations_5.0.py` の使用方法をまとめた技術ドキュメントです。

---

## 1. 翻訳アーキテクチャの基本設計と双方向運用

本プロジェクトでは、ゲームの日本語化データを以下のような**双方向の相互運用（往復）**を前提として設計しています。

```
[マスターデータベース]                     [ゲーム側実行ファイル]
  dictionary.csv    ======(インポート)====>    param/nhMessage.js
        ▲                                          │
        │                                          ▼ (ゲーム実行・手動修正)
        └──────────(エクスポート/逆変換)────────────┘
```

### ファイル一元管理の意義
手動での微調整や、実行時に UI から書き戻されるデータを安全に管理するため、**「すべての翻訳データを単一の `dictionary.csv` で一元管理する」** という方針をとっています。

この一元管理を安全に維持するため、自動管理スクリプト側には**「手動翻訳アセットを絶対に侵食・破壊しない強固な保護ロジック」**が組み込まれています。

## 2. 【実施済み開発実績アーカイブ】解決された課題と実装技術

プロジェクト開発中に解決された主要な技術課題および機能追加の記録です。

### ① クエスト長文メッセージの「行単位分割」仕様の特定
* **解決実績**: `quest.lua` 内の複数行テキストは、ゲーム実行時に UI の表示関数（`putstr` 等）に改行（`\n`）で区切られた「1行ずつ」の短いメッセージとして渡される仕様を特定。パーサを修正し、改行で分割した「行単位」で CSV に登録することでマッチング漏れを解消。

### ② 汎用トークン抽出による取りこぼしの解消
* **解決実績**: NetHack の置換トークン（`%p`, `%d`, `%gP`, `%Ra`, `%oC` 等）の検知ロジックを `r'%[a-zA-Z]+'` に汎用化。漏れなくすべての置換トークンを自動検知して正規表現パターンに移行完了。

### ③ 変数保護（エスケープ）付き自動直訳
* **解決実績**: 翻訳 API 送信前に `$1` を一時的に `__1__` などのプレースホルダーに退避し、翻訳後に元の `$1` に戻す後処理を実装。変数位置が正しく保護・置換された日本語訳を自動生成。

### ④ スペース視認性向上とビルド時自動変換の両立
* **解決実績**: CSV 上の `Source` には通常の「半角スペース ` `」で保存し、JSファイル (`nhMessage.js`) を出力するインポートビルドの段階で、スペースを自動的に `\s+` に変換して書き出す二重構造を導入。CSVの視視性と実行時マッチングの堅牢性を両立。

### ⑤ 未精査動的メッセージ領域のスキャン・集計拡張
* **解決実績**: C言語ソースコード（`src/*.c`）および Lua ファイルからメッセージを自動抽出するパーサ群を追加し、倉庫番/レベル、聞こえる系、状態異常、罠関連、アイテム効果、いのり、アチーブメントの 7 グループを網羅率診断対象として拡張。

## 3. 統合管理スクリプト (`manage_translations_5.0.py`) の使用方法

`tools/dev_scripts/manage_translations_5.0.py` は、辞書データベースの診断、自動スキャン、自動翻訳、クリーンアップを行う CLI ツールです。

### 基本コマンド一覧

| コマンド | 説明 |
| :--- | :--- |
| **`status`** | 翻訳網羅率の診断（未登録文や TODO の残件数などを集計） |
| **`add`** | NetHack 5.0 本家リポジトリから新規・未登録の原文をスキャンして CSV 末尾に追記 |
| **`convert_patterns`** | 置換トークン（`%`等）を含むメッセージを、CSV上で `Pattern`（正規表現）に自動移行 |
| **`translate`** | `=== TODO ===` 付きの未翻訳項目を自動直訳に置換（Google API または ローカルLLM） |
| **`clean`** | ソースコード上に存在しなくなった古い孤立データを安全に削除（不可侵保護あり） |

### 追加オプション（翻訳エンジン用）

| オプション | デフォルト値 | 説明 |
| :--- | :--- | :--- |
| `--limit` | `なし` | 処理する最大翻訳件数を制限（例: `--limit 50`） |
| `--start` | `1` | 未翻訳項目の中での**翻訳開始位置（オフセット）**を指定（例: `--start 100`） |
| `--engine` | `google` | 翻訳エンジンを選択 (`google` または `local`) |
| `--model` | `gemma2` | ローカルLLMのモデル名（例: `gemma2:2b`） |
| `--api-url` | Ollamaデフォルト | API接続先（例: `http://localhost:1234/v1/chat/completions`） |

## 4. 具体的な実行例

### A. 翻訳網羅率の診断
```powershell
python tools/dev_scripts/manage_translations_5.0.py status
```

### B. 辞書データベースのクリーン更新ワークフロー
```powershell
# 1. 最新の未翻訳メッセージをスキャンして追加
python tools/dev_scripts/manage_translations_5.0.py add

# 2. 置換トークン付き英文を正規表現パターンへ自動移行
python tools/dev_scripts/manage_translations_5.0.py convert_patterns

# 3. 古い孤立データを安全にクリーンアップ
python tools/dev_scripts/manage_translations_5.0.py clean
```

### C. 自動翻訳の実行
```powershell
# Google 翻訳 API による自動翻訳 (50件制限)
python tools/dev_scripts/manage_translations_5.0.py translate --limit 50

# ローカル LLM (LM Studio) による自動翻訳
python tools/dev_scripts/manage_translations_5.0.py translate --engine local --api-url http://localhost:1234/v1/chat/completions --model lmstudio
```

## 5. 安全ガード設計（手動翻訳アセットの保護）

`clean` コマンドを含むすべての自動処理において、以下のグループ（手動翻訳・既存重要資産）は**「完全保護グループ（不可侵）」**として定義されています。

- **保護対象グループ**: `Message` (手動翻訳分), `Item`, `Entity`, `Noun`, `Verb`, `Adj`, `Monster`, `Object`

これらのグループに属する行は、ソースコード上に原文が存在するかどうかにかかわらず、**スクリプトの自動クリーンアップによって削除されることは 100% ありません。** 安心して管理ツールを実行してください。
