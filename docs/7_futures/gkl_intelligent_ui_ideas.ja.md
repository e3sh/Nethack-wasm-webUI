# GKL駆動型インテリジェントUI・操作高度化 アイデア＆ロードマップ構想

## 1. 概要と背景

NetHack WebUIにおける「UIとゲームエンジンの進化」は、単なる端末エミュレータ（CUI描画）や形式的なGUI化（単純なテキストボックス配置）を超え、**GKL（Game Knowledge Layer）が文脈と知識をブラウザローカルで統合し、最適な専用インターフェースを提供する「第3段階（インテリジェントUI）」**へと突入しました。

本資料は、今回の「願いビルダー（Wish Builder）」の成功をベースに、今後検討・実装可能なUI高度化アイデアとアーキテクチャ構想をまとめたものです。

---

## 2. インテリジェント入力アシスタント群 (Context-Aware Prompt Assistants)

NetHackのテキスト入力プロンプト（`getlin` 等）を GKL の `PromptPayloadBuilder` が自動検出し、ミスが許されない重要イベントをリッチなGUIでアシストする機能群です。

```
[ NetHack Cコア (getlin) ] ──> [ PromptPayloadBuilder (検知) ] ──> [ 専用モーダルUI ] ──> [ 正規コマンド送信 ]
```

### ① 【実装完了】願いビルダー (Wish Builder)
- **トリガー**: `"For what do you wish?"`（願いの杖、魔法のランプ、祭壇の祈りなど）
- **機能**:
  - 480種以上のアイテムカタログ・カテゴリ分類
  - 定番おすすめプリセット（SDSM、虐殺の巻物、死の杖など）
  - 日本語・英語・略称（`SDSM`, `銀鱗`, `虐殺` 等）のインクリメンタルサジェスト
  - 属性（祝福/呪い、強化値+N、防錆/耐火、個数、油/毒塗り）のGUI設定
  - NetHack Cコアが解釈可能な正式コマンド文字列へのリアルタイム正規化シリアライズ

---

### ② 【構想】虐殺アシスタント (Genocide Assistant)
- **トリガー**: `"What monster do you want to genocide? [type the name or class symbol]"`（虐殺の巻物）
- **課題**: タイポによる不発や、プレイヤー自身の種族（`human` や `elf`）を入力して**即死ゲームオーバー（自己虐殺）**になる悲劇が多発する。
- **提案機能**:
  - **危険モンスターサジェスト**:
    - `L`（マスターリッチ一族）
    - `h`（マインドフレイヤ一族）
    - `c`（コカトリス一族）
    - `&`（大悪魔・デーモン一族）
    - `disenchanter`（ディスエンチャンター）
    - `rust monster`（サビ怪物）
  - **自己虐殺防止セーフティガード ⚠️**:
    - プレイヤーの現在種族（`human`, `elf`, `dwarf` 等）が入力・選択された場合、**「⚠️ 警告: 自身が虐殺され即死します！」** と赤くハイライトして確認を要求。
  - **単体 / クラス（大文字シンボル）選択の可視化**:
    - 「特定モンスター1種」か「シンボル一族全体」かをタブやトグルで直感的に切り替え。

---

### ③ 【構想】変化制御アシスタント (Polymorph Control Assistant)
- **トリガー**: `"You feel a change coming over you. What do you want to turn into?"`（変化の罠、変化の杖など）
- **提案機能**:
  - **なりたいモンスターの視覚的選択**:
    - ドラゴン（各色ブレス・飛行）、マスターリッチ（魔法・耐性）、巨人の一覧。
  - **変身後の特性プレビュー**:
    - 飛行（Flying）、耐性、武器・防具の装着可否、サイズ（装備破壊リスクの有無）。

---

### ④ 文字彫り・エルベレスアシスタント (Engraving Assistant)
- **現在の実装状況**: 
  - 危機的状況（HP低下時や凶悪モンスター接近時）には、GKLの `AssistSignalSynthesizer` が最優先シグナルを生成し、HUD上に **「🛡️ Elberethを彫る」** のワンタップ緊急実行ボタンがすでに自動出現するよう実装済み。
- **将来の拡張アイデア**:
  - 通常時に手動で `#engrave`（`E`）を押した際、手持ちの道具（指輪、アサメ、杖、素手など）に応じた摩耗ターン数・成功率の事前表示や、彫る文字（Elbereth等）のクイック選択ダイアログ。

---

### ⑤ 未識別アイテム命名・コールアシスタント (`#call` / `#name`)
- **現在の実装状況**:
  - アイテム使用時や効果発生時に、ログメッセージから仮の識別メモを自動登録する機能が実装済み。
- **将来の拡張アイデア**:
  - 手動で `#call` / `#name` を行った際、過去の同種族アイテム（例: 「価格300の巻物」の候補: `genocide`, `punishment` 等）の候補サジェストや、「価格識別メモ（100zm, 300zm）」のワンタップ付与。

## 3. ビジュアル・コンテナUI (Visual Container Management)

従来の文字リスト型メニュー（`apply` や `#tip`）を刷新し、モダンRPG風の2カラム視覚的インベントリを実現する構想です。

```
┌─────────────────────────────────────────────────────────────┐
│  🎒 魔法の利いた鞄 (Bag of Holding)          容量: 120/500 wt │
├──────────────────────────────┬──────────────────────────────┤
│ 【 プレイヤーの所持品 】    │ 【 鞄の中身 】               │
│  [🗡️ +2 ロングソード]        │  [📜 虐殺の巻物 ×2]          │
│  [🛡️ 銀ドラ鱗鎧]            │  [🧪 完全回復の薬 ×3]        │
│  [🧪 聖水 ×4]                │  [🪄 死の杖 (0:3)]           │
│  [🪄 変化の杖] ⚠️            │  [💰 1500 ゴールド]          │
│  [🍞 保存食 ×5]              │  [💎 ダイヤモンド ×4]        │
├──────────────────────────────┴──────────────────────────────┤
│  操作: クリックまたはドラッグで出し入れ                      │
│  [ 一括収納 (宝石・金貨) ]   [ 整理 ]   [ 閉じる ]          │
└─────────────────────────────────────────────────────────────┘
```

### 主な特徴とGKLアシスト
1. **タイルアイコンによる一覧性**:
   - GKLの `OBJECT_TILEMAP_NAMES` を用いたグラフィカルな表示。
2. **鞄爆発（全ロスト）の完全防止 ⚠️**:
   - 魔法の利いた鞄（Bag of Holding）に「変化の杖」や「別の魔法の利いた鞄」を入れようとすると、GKLが **「⚠️ 危険: 入れると鞄が大爆発して中身が消滅します！」** と警告。
3. **ワンタップ一括収納**:
   - 宝石・金貨・余剰食料の一括収納。
4. **重量・容積のプログレスバー表示**:
   - 鞄の重量軽減率（1/4等）を反映したリアルタイム積載率バー。

## 4. ビジュアル魔法詠唱ダイアログ (Visual Spellcasting UI)

- **トリガー**: `cast spell`（`Z`）
- **提案機能**:
  - 習得済みスペルを系統別（攻撃、回復、補助、脱出）にグリッド配置。
  - 現在の装備ペナルティを考慮した**「詠唱成功率（%）」**、消費MP、効果範囲（直進ビーム、周囲、自身）の可視化。

---

## 5. アーキテクチャ設計原則 (Design Principles)

本プロジェクトのインテリジェントUI拡張において、厳格に維持すべき原則：

1. **SSOT（Single Source of Truth: 単一の真実源）の遵守**:
   - アイテム名、モンスター名、カテゴリ、属性対訳などの辞書データはUIや個別サービス内に重複して持たず、`TranslationEngine`（`dictionary.csv` / `nhMessage.js`）および GKL コアナレッジから一元解決する。
2. **Cコア（Wasm）の非改変（Zero Core Pollution）**:
   - NetHack C言語コアは標準のAPI（`getlin`, `menu` 等）を呼び出すだけであり、ブラウザ側のGKLが文脈を判定してリッチUIに昇華させる。
3. **ブラウザローカルでの超高速動作**:
   - サジェスト、属性検証、コマンド生成はすべてクライアント（JS）ローカルでミリ秒未満で完了させる。
4. **既存テスト・後方互換性の維持**:
   - キーボードのみの伝統的なCUI操作環境も常に完全にサポートする（フォールバックの確保）。
