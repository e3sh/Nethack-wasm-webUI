# シレン風GamePad専用クライアント＆GKL連携ゲートウェイ構想

**作成日**: 2026-09-28  
**ステータス**: 構想・将来計画 (Future Vision)  
**関連モジュール**: `ContextActionEngine`, `ActionRecipeFactory`, `GamepadManager`, `WebUICore`

---

## 1. 背景と経緯：かつて諦めた構想のブレイクスルー

Legacyクライアント時代（`GpadToKey.js`, `mobile.html`）にゲームパッド操作を実装した際、4×7のボタンインジケータ（XHB風HUD）やYN/MENUなどのコンテキストオーバーレイを開発していた。しかし、当時の入力系は**「パッドボタン ＝ 単一キーコード（文字コード）」**をNetHack本体に送信する仕組みであったため、以下の壁に直面し、ワンボタン化の構想は一度断念せざるを得なかった：

1. **状況判定の不在**: ゲーム内状態（足元に階段があるか、アイテムがあるか、目の前が閉じたドアか）を入力側が知る術がなかった。
2. **シーケンス入力の壁**: 「ドアを開ける（`o` + 方向）」「アイテムを拾う（`,`）」「階段を降りる（`>`）」など、複数キーや異なる文字を状況に応じて打ち分ける必要があった。

### GKL（Game Knowledge Layer）による雪解け
現在、WebUIプロジェクトには以下のアーキテクチャが確立された：
- **`ContextActionEngine`**: 周囲地形、足元、隣接モンスター、所持品から「今最も自然なアクション」を高精度に推論。
- **`ActionRecipeFactory` / `InteractiveRequestController`**: 複雑なコマンド列（キーシーケンス）をセマンティックな1つのレシピとして自動実行。

これにより、**「足元の状況や目の前の対象に合わせて、Aボタン1つで最適な行動を自動実行する」という構想が完全に現実解となった。**

## 2. コンセプト：「最高の導入クライアント (Gateway Client)」

本構想は、既存の多機能デスクトップ向けUI（`index.html`）にパッド操作を無理やり詰め込むのではなく、**「最初からゲームパッド/携帯ゲーム機（Steam Deck等）向けに設計された専用クライアント（例: `console.html`）」**として切り出す。

### 基本方針
1. **シレン・コンソールライクな直感性**:
   - キーボードの存在を忘れ、左スティック/十字キーとA/B/X/Yボタンだけでサクサク探索できる極上の手触り。
2. **邪魔にならないミニマルHUD（オンデマンド表示）**:
   - 常時インジケータは表示せず、画面をダンジョンに全振りする。
   - 「必要な時だけ」「ボタンを押した時だけ」ガイドがフワッと浮かぶ。
3. **本家コマンドへの架け橋 (Learning Bridge)**:
   - パッド操作とキーボード入力は完全に並行動作可能。
   - パッド操作のガイドやメニューに**「本家NetHackだと何のキーなのか（英単語の由来も含む）」**のヒントを添える。
   - プレイヤーはシレン感覚で気持ちよく遊びながら、自然とNetHack本来のキー体系を学習でき、熟練後はデスクトップ版や本家CLIへステップアップできる。

## 3. 操作体系：デュアルアクセス設計（網羅性と即応性の両立）

NetHackの膨大な操作をパッドに収める鍵は、**「アイコンインベントリの推奨操作（網羅性）」** と **「専用ショートカット（即応性）」** の2重構造にある。

```
┌─────────────────────────────────────────────────────────────┐
│ 【網羅性】 アイコンインベントリ (Yボタン ➔ 推奨操作)        │
│   ・アイテムを選ぶだけで「飲む / 読む / 使う / 投げる / 浸す」│
│     などの推奨操作がGUIでサジェストされ、全アイテムを網羅  │
│   ・ペーパードールUIにより、武器・防具・指輪も直感的に装備  │
├─────────────────────────────────────────────────────────────┤
│ 【即応性】 緊急サバイバル専用ボタン (LT / RT トリガー)      │
│   ・「今すぐエルベレスを書かないと死ぬ！」「今すぐ回復！」   │
│   ・インベントリを開く1テンポすら惜しい極限状態で即時発動   │
└─────────────────────────────────────────────────────────────┘
```

### デフォルトボタンマッピング (`GPAD_DEFAULT_SEMANTIC`)

#### ① 通常面 (`NORMAL`)：探索の9割をカバー
| ボタン | ラベル | 割り当て | 役割 |
| :--- | :--- | :--- | :--- |
| **A** | **行動** | `action: "ACTION:CONTEXT_PRIMARY"` | **足元（昇降・拾う）、隣接（ドア開・攻撃）の自動判定** |
| **B** | **待機** | `action: "ACTION:WAIT_ONE_TURN"` | 1ターン経過 (`.`) / ダイアログキャンセル / 足踏み |
| **X** | **射撃** | `action: "ACTION:RANGED_FIRE"` | Quiverスロットからの射撃・投擲 (`f` / `t`) |
| **Y** | **道具袋** | `signal: "SIGNAL:TOGGLE_INVENTORY"` | IconInventory ＆ ペーパードールUIの開閉 |
| **START** | **拡張** | `key: ["Digit3", "ShiftLeft"]` | # 拡張コマンド入力プロンプト |
| **BACK** | **保存** | `key: ["KeyS", "ShiftLeft"]` | セーブ終了 (S) |
| **L3** | **調べる** | `key: ["Quote"]` | 現在地・対象調査 (:) |
| **R3** | **探す** | `key: ["KeyS"]` | 隠しドア・罠の探索 (s) |

#### ② 左トリガー (`LT`)：消耗品・回復パレット
| ボタン | ラベル | 割り当て | 本家キー対応 |
| :--- | :--- | :--- | :--- |
| **A** | **飲む** | `key: ["KeyQ"]` | ポーション (`q: quaff`) |
| **B** | **食べる** | `key: ["KeyE"]` | 食料摂取 (`e: eat`) |
| **X** | **読む** | `key: ["KeyR"]` | 巻物・魔法書 (`r: read`) |
| **Y** | **呪文** | `signal: "SIGNAL:OPEN_SPELLS"` | 呪文一覧・詠唱 (`Z: zap`) |

#### ③ 右トリガー (`RT`)：緊急回避・サバイバルパレット
| ボタン | ラベル | 割り当て | 本家キー対応 / 役割 |
| :--- | :--- | :--- | :--- |
| **A** | **道具** | `key: ["KeyA"]` | ツール使用 (`a: apply`) |
| **B** | **杖振る** | `key: ["KeyZ"]` | 脱出用ワンドの即時発射 (`z: zap`) |
| **X** | **エルベレス** | `action: "ACTION:ENGRAVE_ELBERETH"` | **【緊急】床に指でElberethをワンボタンで刻印** |
| **Y** | **祈る** | `action: "ACTION:EXT_PRAY"` | **【緊急】瀕死時の神への祈り (`#pray`)** |

#### ④ バンパー (`LB / RB`)：シレン式移動モディファイア
- **[LB] (L1)**: **斜め移動固定**（ホールド中は斜め4方向のみ受け付け、誤爆死をゼロに）
- **[RB] (R1)**: **ダッシュ走行**（通路の曲がり角や敵に当たるまで一気に直進: `G` + 方向）

## 4. オンデマンド・インプットガイドと本家ヒント表現

画面の没入感を妨げないため、ガイドは**「必要な瞬間のみ」**出現する。

### ① コンテキスト・ポップアップ（必要な時だけフワッと出現）
インタラクト可能なマスに乗った/面した瞬間、キャラ付近または画面下部に控えめなピルバッジが表示される。離れると消滅。

```text
[ 階段の上 ]  ──>  [A] 降りる  [ > ]
[ 金貨の上 ]  ──>  [A] 拾う    [ , ]
[ ドアの前 ]  ──>  [A] 開ける  [ o + 方向 ]
```

### ② モディファイア・HUD（LT/RTホールド中のみ出現）
LT（呪文・消耗品）またはRT（道具）を指で引き込んでいる間だけ、画面右下に十字状のガイドがフェードイン。離すと即座に消滅。

```text
       【LT ホールド中】
             [Y] 祈る  [ #pray ]
  [X] 読む              [B] 飲む
   [ r: read ]           [ q: quaff ]
             [A] 唱える
              [ Z: zap/cast ]
```
> **ヒントの教育的効果**:
> なぜそのキーなのか（例: `q: quaff` や `r: read`）が自然と視界に入るため、英単語の略称とキー配置が無理なく脳に刷り込まれる。

### ③ 道具メニュー（Yボタン）での階層アクション
Yボタンで開く縦型インベントリからアイテムを選択した際、利用可能なサブコマンドと本家キーを併記：

```text
┌──────────────────────────────────────┐
│ [無色透明なポーション]               │
│   ▸ [A] 飲む        [ q: quaff ]     │
│     [X] 投げる      [ t: throw ]     │
│     [Y] 置く        [ d: drop ]      │
│     [B] 浸す        [ #dip ]         │
└──────────────────────────────────────┘
```

## 5. アーキテクチャ構成：GpadToKeyマッピングのシグナル拡張

本構想の最大の強みは、**既存の `GpadToKey` / `GamepadManager.js` のマッピング機構をそのまま活かせる点**にある。

### マッピング定義（JSON）のシグナル拡張
従来の `key: ["Space"]` といったキーコード配列の代わりに、システムが理解できる「セマンティックアクション」や「UI制御シグナル」をマップ値としてアサイン可能にする。

```json
{
  "NORMAL": {
    "A": { "label": "アクション", "action": "ACTION:CONTEXT_PRIMARY" },
    "B": { "label": "待機",       "action": "ACTION:WAIT_ONE_TURN" },
    "X": { "label": "投擲",       "key": ["t"] },
    "Y": { "label": "道具袋",     "signal": "SIGNAL:TOGGLE_INVENTORY" },
    "LB": { "label": "斜め固定",  "modifier": "DIAGONAL_LOCK" },
    "RB": { "label": "ダッシュ",  "modifier": "DASH_RUN" }
  },
  "LT": {
    "A": { "label": "呪文",       "signal": "SIGNAL:OPEN_SPELLS" },
    "B": { "label": "飲む",       "key": ["q"] },
    "X": { "label": "読む",       "key": ["r"] },
    "Y": { "label": "祈る",       "key": ["#", "p", "r", "a", "y", "Enter"] }
  }
}
```

### ディスパッチフロー
既存のポーリングループおよびLB/RB/LT/RT修飾子判定、localStorage同期（`nh.gpadAssign`）のコードを1行も捨てることなく、入力受取層でプレフィックスを判定してルーティングする：

1. **`ACTION:` プレフィックス**:
   - `ContextActionEngine` の最優先アクション解決や、`ActionRecipeFactory` へのディスパッチを行う。
2. **`SIGNAL:` プレフィックス**:
   - `ModalStackController` やUI側のモーダル開閉・トグルイベントを直接発火する。
3. **通常のキーコード / 配列**:
   - 従来通り NetHack WASM コアへの直接入力として透過（パススルー）する。

これにより、専用クライアントの新設時だけでなく、**マッピング設定（JSON）を切り替えるだけで既存のデスクトップ版クライアントでも即座にスマート操作が機能する。**

### システム主導のコンテキストマップ切替（State-Driven Map Swapping）

`GamepadManager.js` に元々備わっていた `applyContextOverlay(KA, context)` 機構を最大限に活かし、**システム（`ModalStackController` や `SignalDetector`）から現在のUIステートをコンテキストとして渡す**ことで、ボタンマップを動的にスワップする。

```
                    ┌─── [通常探索時] ─────────> NORMAL マップ (A:コンテキスト / RT:サバイバル)
                    │
システムの状態 ─────┼─── [インベントリ開] ─────> MODAL_INVENTORY マップ (A:決定 / B:閉じる / LB・RB:タブ切替)
 (ModalStack / GKL) │
                    ├─── [呪文・射撃の方向指定] ──> DIRECTION マップ (十字:方向決定 / B:キャンセル)
                    │
                    └─── [Yes/No 選択プロンプト] ──> YN マップ (A: Yes / B: No)
```

#### コンテキスト別マップの役割分担
1. **`NORMAL` (通常探索)**:
   - 十字/スティック: 移動 / A: 状況適応 / B: 待機 / Y: インベントリ / LT・RT: パレット
2. **`DIALOG_SAFE` / `MODAL_INVENTORY` (ダイアログ・メニュー表示中)**:
   - **完全誤爆防止 (Fail-Safe)**: 移動や攻撃など「ゲーム内ターンを経過させる」入力を100%遮断
   - 十字上下: 項目フォーカス移動（前 / 次）
   - 十字左右: ページ送り / 数量増減スライダー
   - Aボタン: 決定 / 選択 / サブメニュー展開
   - Bボタン: キャンセル / 閉じる (ESC)
   - Xボタン: サブアクション (詳細 / 捨てる / チェック)
   - LB / RB: カテゴリタブ切り替え (武器/防具/巻物...)
3. **`DIRECTION` (射撃・呪文・ツールの方向選択時)**:
   - 十字/スティック: 8方向指定 / A: 決定・発射 / B: キャンセル
4. **`YN` / `LIN` (プロンプト応答時)**:
   - 既存の overlay 処理（A: Yes / B: No、A: Backspace / X: Enter 等）がそのまま適用

これにより、パッド側に複雑な状態管理を持たせることなく、システム側のUI状態変化と100%同期して完璧なキーバインド制御が可能となり、「ダイアログを開いているつもりが移動して敵に殴られる」といったNetHack特有の事故を完全に撲滅できる。

## 6. クライアントとコアの接続関係

Coreレイヤーの改修は最小限で済み、クライアント層に専用ビュー・コントローラーを追加する。

```
┌─────────────────────────────────────────────────────────────┐
│ 【新設】 専用クライアント (例: console.html / GamepadClient)  │
│   ├── GamepadInputController (スティック・LB斜め・RB走行制御)│
│   ├── ContextHintPresenter (状況適応ガイド ＆ 本家キー描画) │
│   ├── ShirenInventoryDrawer (Yボタン用スライドインベントリ) │
│   └── FocusedViewportRenderer (キャラ中央追従カメラ)        │
└─────────────────────────────┬───────────────────────────────┘
                              │
┌─────────────────────────────▼───────────────────────────────┐
│ 【既存・完全再利用】 WebUICore / GKL 知識レイヤー          │
│   ├── GamepadManager (シグナル対応マッピング解決)           │
│   ├── ContextActionEngine (足元・周囲・優先度の自動判定)     │
│   ├── ActionRecipeFactory (シーケンス入力のセマンティック実行)│
│   ├── AreaStateManager / InventoryStateManager (状態追跡)  │
│   └── NetHackWasmDriver / WebUICore                         │
└─────────────────────────────────────────────────────────────┘
```

## 7. 段階的実装ロードマップ (PoC Plan)

### Step 1: コア操作PoC（最優先の体験検証）
- 専用HTML（`examples/gamepad-client/index.html` 等）の作成。
- スティック移動、LB斜め固定、RBダッシュの入力実装。
- `ContextActionEngine` の Priority 1位アクションを Aボタンにバインド。
- 足元に階段/アイテムがある時、`[A] 降りる [ > ]` ガイドを出し、Aボタンで正しく動作することを検証。

### Step 2: オンデマンドHUD & パレット実装
- LT/RTホールド時のみフェードインする十字/ラジアルパレットの実装。
- パレットからの魔法・ポーション・巻物・道具アクションの発火。

### Step 3: シレン風縦型インベントリ
- Yボタンで開閉するシンプルな縦型アイテムドロワー。
- 十字キー選択 ＋ Aボタンサブコマンド（飲む・投げる・置く等）の実行。

### Step 4: 画面演出・解像度最適化
- キャラクター追従カメラ（1280x800 Steam Deck解像度へのジャストフィット）。
- ミニマルなHPバー・満腹度表示、1行メッセージHUD。
