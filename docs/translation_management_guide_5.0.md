# NetHack 5.0 翻訳システム統合管理ガイド

本書は、NetHack Wasm WebUI 移植プロジェクトにおける NetHack 5.0 対応の翻訳管理システム、本日得られた技術的知見、および統合管理スクリプト `manage_translations_5.0.py` の使用方法をまとめた技術ドキュメントです。

---

## 1. 翻訳アーキテクチャの基本設計と双方向運用

本プロジェクトでは、ゲームの日本語化データを以下のような**双方向の相互運用（往復）**を前提として設計しています。

```
[マスターデータベース]                     [ゲーム側実行ファイル]
  dictionary.csv    ======(インポート)====>    param/nhMessage.js
        ▲                                          │
        │                                          ▼ (ゲーム実行・手動修正)
        └──────────(エクスポート/逆変換)────────────┘
```

### ファイル一元管理の意義
手動での微調整や、実行時に UI から書き戻されるデータを安全に管理するため、**「すべての翻訳データを単一の `dictionary.csv` で一元管理する」** という方針をとっています。
ファイルを物理的に分割（アセット用とスキャン用に分割など）してしまうと、インポート時に削ぎ落とされるメタ情報（`=== TODO ===` フラグなど）や、書き戻し時のファイル割り当てが崩れて整合性が保てなくなります。

この一元管理を安全に維持するため、自動管理スクリプト側には**「手動翻訳アセットを絶対に侵食・破壊しない強固な保護ロジック」**が組み込まれています。

## 2. 本日の作業内容と解決した課題

### ① クエスト長文メッセージの「行単位分割」仕様の特定
* **知見**: `quest.lua` 内の `text = [[...]]` にある複数行のテキストは、ゲーム実行時には UI の表示関数（`putstr` 等）に改行（`\n`）で区切られた「1行ずつ」の短いメッセージとして流れてきます。そのため、パーサ側で改行を結合して1つの長い段落にしてしまうと、ゲーム中で部分的に流れる英文と正規表現パターンがマッチせず、翻訳が適用されなくなってしまいます。
* **対策**: スキャナ（`parse_quest`）を再修正し、複数行テキストを改行で分割した「行単位」で CSV に登録する正しい仕様に復元しました。これにより、実行時のマッチング漏れを防ぐと同時に、翻訳対象が短くなり直訳クオリティも向上しました。

### ② 汎用トークン抽出による取りこぼしの解消
* **知見**: NetHack の置換トークン（`%p`, `%d` 等）の直後には、`%gP`, `%Ra`, `%oC` などのサフィックス（活用や複数形などを表すアルファベット）が続きます。
* **対策**: トークン検出ロジックを `r'%[a-zA-Z]+'` による正規表現抽出へ汎用化しました。これにより、`%i`, `%gP`, `%Ra`, `%Z` など漏れなくすべての置換トークンを自動検知して正規表現パターンに移行できるようになりました。

### ③ 変数保護（エスケープ）付き自動直訳
* **知見**: Google 翻訳 API に `$1` や `$2` などの変数記号を含んだまま送信すると、翻訳エンジンによって記号が消去されたり、順番が破壊されたりするリスクがありました。
* **対策**: 送信前に `$1` を一時的に `__1__` のようなプレースホルダーに安全に退避し、翻訳後に元の `$1` に戻す後処理を実装しました。これにより、日本語の自然な語順（例: `$2 への忠誠を裏切ったため、あなたは $1 から追放されました`）に合わせて、変数位置が正しく入れ替わった翻訳文が得られます。

### ④ スペース視認性向上とビルド時自動変換の両立
* **知見**: CSV 上の `Source` 列に `\s+`（正規表現のスペース表現）が大量に含まれると、人間がパッと見たときに原文が非常に読みにくくなります。
* **対策**: CSV 上の `Source` には通常の「半角スペース ` `」で保存し、JSファイル (`nhMessage.js`) を出力するインポートビルドの段階で、スペースを自動的に `\s+` に変換して書き出す二重構造を導入しました。これにより、**CSVの視認性**と**実行時のマッチングの堅牢性**を完璧に両立しました。

## 3. 統合管理スクリプトの使用方法

新設された `tools/dev_scripts/manage_translations_5.0.py` は、以下のコマンドを通じて辞書データベースを安全かつスマートに管理します。

### 基本コマンド一覧

| コマンド | 説明 |
| :--- | :--- |
| `status` | 翻訳網羅率の診断（未登録文や TODO の残件数などを集計） |
| `add` | NetHack 5.0 本家リポジトリから新規・未登録の原文をスキャンして CSV 末尾に追記 |
| `convert_patterns` | 置換トークン（`%`等）を含むメッセージを、CSV上で `Pattern`（正規表現）に自動移行 |
| `translate` | `=== TODO ===` 付きの未翻訳項目を自動直訳に置換（Google API または ローカルLLM） |
| `clean` | ソースコード上に存在しなくなった古い孤立データ（過去の段落長文パターンなど）を安全に削除 |

### 追加オプション（翻訳エンジン用）

| オプション | デフォルト値 | 説明 |
| :--- | :--- | :--- |
| `--engine` | `google` | 翻訳エンジンを選択 (`google` または `local`) |
| `--model` | `gemma2` | ローカルLLMのモデル名（例: `gemma2:2b`） |
| `--api-url` | Ollamaデフォルト | API接続先（例: `http://localhost:1234/v1/chat/completions`） |

### 具体的な使用例

#### A. 辞書データベースの クリーンな更新ワークフロー
新しくスキャンし直し、不要な古いパターンを除去して JS にインポートする際の一連のコマンドです。

```powershell
# 1. 5.0本家から最新の未翻訳メッセージをスキャンして追加
python tools/dev_scripts/manage_translations_5.0.py add

# 2. 置換トークン付き英文を正規表現パターンへ自動移行
python tools/dev_scripts/manage_translations_5.0.py convert_patterns

# 3. 古い孤立データ（段落結合されていた長文など）をCSVから安全にクリーンアップ
python tools/dev_scripts/manage_translations_5.0.py clean
```

#### B. 仮翻訳（自動直訳）の実行
未翻訳項目に対して、Google 翻訳 API またはローカルLLMを用いて日本語直訳を自動適用します。
* **安全機能**: すでに日本語の翻訳（ひらがな・カタカナ・漢字）が登録されている項目は**自動的に検知してスキップ**するため、二重使用を防ぎます。
* **割り込み保護**: 翻訳中に `Ctrl + C` で安全に処理を中断・その時点までの結果を保存して終了できます。

##### ① Google 翻訳 API（従来通り・高速）
```powershell
# 未翻訳項目をすべて自動翻訳（10件ごとに中間セーブ）
python tools/dev_scripts/manage_translations_5.0.py translate

# 件数を制限してテスト翻訳したい場合 (--limit オプション)
python tools/dev_scripts/manage_translations_5.0.py translate --limit 10
```

##### ② ローカルLLM (LM Studio - 推奨)
LM Studio の「Local Server」を起動した状態で、OpenAI 互換エンドポイントを指定して実行します。
```powershell
python tools/dev_scripts/manage_translations_5.0.py translate --engine local --api-url http://localhost:1234/v1/chat/completions --model lmstudio
```

##### ③ ローカルLLM (Ollama)
Ollama が起動している状態で、モデル名を指定して実行します（あらかじめ `ollama pull gemma2:2b` を実行しておきます）。
```powershell
python tools/dev_scripts/manage_translations_5.0.py translate --engine local --model gemma2:2b
```

#### C. JS ファイルへのビルド反映
辞書データをゲーム側実行ファイルへ反映します。
```powershell
python tools/dict_converter.py import dictionary.csv
```

## 4. 安全ガード設計（手動翻訳アセットの保護）

`clean` コマンドを含むすべての自動処理において、以下のグループ（手動翻訳・既存重要資産）は**「完全保護グループ（不可侵）」**として定義されています。

* **保護対象グループ**: `Message` (手動翻訳分), `Item`, `Entity`, `Noun`, `Verb`, `Adj`, `Monster`, `Object`

これらのグループに属する行は、ソースコード上に原文が存在するかどうかにかかわらず、**スクリプトの自動クリーンアップによって削除されることは 100% ありません。** 安心して管理ツールを実行してください。
