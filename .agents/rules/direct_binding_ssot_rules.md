# Cコア直接結合（DirectBinding SSOT）＆ 推論排除ルール

## 1. Cコア絶対真値（SSOT）と JS 土管化の原則
- **画面描画、グリフ番号、ダンジョン構造の決定権は 100% NetHack C コアにある。**
  - C コアからストリーミングされる `print_glyph`
  - C コアのメモリダンプ `levl[x][y].glyph` (`_cachedLevelGlyphs`)
- **禁止事項**:
  - ❌ **JS 側で地形 `typ` や数値パラメータからグリフ番号を推測・捏造・逆算する行為。**
  - ❌ `getGlyphForTerrainType` のような推論ロジックの呼び出し・新設・延命。
  - ❌ 「C コアの直接グリフが取れなかった時のため」と称して大雑把な仮グリフ（例: 壁なら何でも 3930 等）を捏造して真値（genuine）と偽る行為。

## 2. 受信イベント（print_glyph）の絶対優先・保護
- C コアから送信された `print_glyph`（特に地形 `TERRAIN`）は、C コア自らが決定した最高精度の確定描画値である。
- **禁止事項**:
  - ❌ その後のキャッシュ同期（`dumpLevelMap`, `syncFromDirectBinding` 等）によって、受信済みの正確な地形（角壁・ドア・通路等）を推論値やデフォルト値で上書き（Re-clobber / 地形化け）する行為。
  - ❌ 物理的変化（掘削による typ 変化やドア破壊等）がない限り、受信した地形グリフは不可侵として保護しなければならない。

## 3. レガシー推論・ゾンビフォールバックの即時全廃原則
- DirectBinding Native への移行完了後、過去の推論コード（`TerrainInferenceEngine` 等）を「一応念のため」と温存してはならない。
- C コアから直接取得できる値が存在する場合、古い推論パス・フォールバックは即座に完全バイパスまたは削除する。
- 不要になった推論に依存したテストやコードを見つけた場合、惰性で互換性を保つのではなく、SSOT 原則に沿ってテストおよびコードを純化する。

## 4. 実装前の自己検閲（Self-Check）義務
コードを変更する前に、AI は以下の 3 点を必ず自問自答すること：
1. 「JS 側で C コアのグリフ番号を勝手に推測・計算・捏造していないか？」
2. 「C コアから届いた確定グリフを、定期同期やキャッシュ展開が破壊（化け）させていないか？」
3. 「役目を終えた過去の推論ロジックを無批判に真似して呼び出していないか？」
